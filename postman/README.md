# Postman 接口测试

对 RuoYi-Vue 核心接口做手工 + 半自动接口测试，覆盖 **28 个接口 / 5 组场景**，每个请求都带断言（`pm.test`），可在 Collection Runner 中批量执行并输出结果。

## 一、文件说明

| 文件 | 用途 |
| --- | --- |
| `RuoYi-Vue.postman_collection.json` | 接口集合，含 5 个文件夹、28 个请求、断言脚本 |
| `RuoYi-Vue.postman_environment.json` | 环境变量，含本地服务地址与账号 |

## 二、导入与准备

1. 打开 Postman → `Import` → 拖入或选择上述两个 JSON 文件。
2. 右上角环境选择器切换到 **「RuoYi-Vue 本地环境」**。
3. **关闭图形验证码**（推荐）：「系统管理 → 参数设置」→ `sys.account.captchaEnabled` → `false`。
   若不关闭，先执行「01 登录鉴权」里的 *获取图形验证码*，人工识别后把 uuid 与验证码字符分别填入 `captchaUuid`、`captchaCode` 变量。

## 三、变量说明

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `baseUrl` | `http://localhost:8080` | 后端服务地址 |
| `username` / `password` | `admin` / `admin123` | 登录账号 |
| `token` | 空 | 登录成功后由脚本自动写入，无需手工填 |
| `captchaCode` / `captchaUuid` | 空 | 验证码开启时需手工填 |
| `newUserName` | `apitest01` | 测试新增用户用的唯一账号名，重复执行请改值 |
| `userId` | 空 | 新增后自动回写，供详情 / 重置密码 / 删除使用 |
| `offlineToken` | 空 | 强退在线用户需先从在线列表复制的 tokenId |
| `lowPrivToken` | 空 | 无权限账号（test01）的 token，用于越权校验 |

## 四、接口清单

| 分组 | 接口数 | 覆盖内容 |
| --- | --- | --- |
| 01 登录鉴权 | 7 | 获取验证码、登录成功、登录失败（密码错误）、验证码一次性校验、获取用户信息、获取动态路由、退出登录 |
| 02 用户管理 | 8 | 列表分页、新增、按用户名查询、详情回显、重复账号拦截、非法手机号（校验缺口）、重置密码、删除 |
| 03 角色与组织 | 5 | 角色列表、菜单列表、部门列表、岗位列表、字典类型列表 |
| 04 系统监控 | 5 | 在线用户、强退在线用户、定时任务、调度日志、服务监控 |
| 05 鉴权异常校验 | 3 | 无 token 访问、伪造 token 访问、无权限角色访问受限接口 |

## 五、断言覆盖

每个请求至少校验两层，共三层：

- **HTTP 层**：状态码是否 200（鉴权类请求断言 401）；
- **业务层**：响应体 `code` 是否为 200，失败请求是否真正返回非 200 与可读提示；
- **数据层**：关键字段是否存在且符合预期，如 `total > 0`、`rows` 为数组、`userName` 与新增一致、角色关联非空。

> **注意 RuoYi-Vue 的鉴权失败返回形态**：未认证时后端由 `AuthenticationEntryPointImpl` 直接写出响应体，**HTTP 状态码仍是 200，只有 `body.code` 为 401**（`msg` 为「请求访问：xxx，认证失败，无法访问系统资源」）。
> 因此只看 HTTP 状态码会误判为「请求成功」，**接口断言必须校验 `body.code`**。这也是本集合在 HTTP 层之外单独做业务层断言的原因。

登录请求的断言会把返回的 `token` 同时写入**集合变量**与**环境变量**（环境未激活时只写集合变量），后续请求通过集合级 `Bearer {{token}}` 自动携带，因此**必须先跑登录，再跑其他分组**。变量取值优先级为「环境 > 集合」，环境里若残留一个空的 `token`，会遮蔽集合里的值，故环境变量文件中未定义 `token`，由登录脚本运行时写入。

部分请求的断言脚本会自动回写变量（登录取 token、按用户名查询取 userId），支持一键串行跑通整条链路。

## 六、执行方式

- 单个调试：直接点击请求 `Send`，看下方 Test Results。
- 批量执行：右键集合 → `Run collection` → 选择环境 → 勾选「Persist variable」→ Run。
- 注意执行顺序：`01 → 02 → 03 → 04 → 05`。退出登录会失效当前 token，单独放在 01 分组末尾；若批量执行后 token 失效，重新跑一次登录即可。

## 七、测试中发现的接口层问题

- **手机号格式未在后端校验**：前端有限制，绕过前端直接调 `/system/user` 传 `12345678901` 可成功创建，说明前后端校验不一致（对应缺陷 BUG-003，见 `bug-list/bug-list.md`）。
- 该项在集合中已固化为独立请求「新增用户传非法手机号（校验缺口验证）」，断言为「应被拦截」，当前执行结果会失败——这正是缺陷成立的证据，修复后该断言会自动通过。
