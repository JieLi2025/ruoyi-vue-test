# RuoYi-Vue 后台管理系统 · 测试实践

在本地部署的开源后台管理系统上，完整走通一轮测试流程：**测试计划 → 用例设计 → 用例执行 → 缺陷记录 → 接口测试 → 自动化回归 → 测试总结**，并针对 RBAC 权限模型做了权限校验专项。

---

## 一、项目说明

被测系统为开源项目 **RuoYi-Vue**（Spring Boot + Vue 前后端分离架构）。

本项目是**个人测试实践**，不是商业项目：全部用例、执行记录与缺陷均基于本人在本地部署环境中的实际操作，不涉及任何公司内部数据与业务信息。

用例字段统一为：用例 ID、模块、用例标题、优先级、前置条件、操作步骤、预期结果、实际结果、是否通过、备注。**前置条件写明登录账号与页面路径**，保证任何人拿到用例可直接照做。

## 五、用例设计方法

- **等价类划分**：用户名、手机号、验证码、cron 表达式等输入项划分有效/无效等价类。
- **边界值分析**：空值、超长输入、密码长度边界、分页条数边界。
- **场景法**：串联业务流程，如「新增用户 → 分配角色 → 用该账号登录 → 验证菜单权限」。
- **错误推测**：针对易出问题点设计反向用例，如重复提交、删除被引用数据、删除自身账号。
- **权限专项**：围绕 RBAC 验证「菜单可见性 / 按钮可用性 / 接口鉴权」三层是否一致。

## 六、接口测试（Postman）

覆盖 **28 个接口 / 5 组场景**：登录鉴权 7 个、用户管理 8 个、角色与组织 5 个、系统监控 5 个、鉴权异常 3 个。

每个请求都写了两层以上断言（HTTP 状态码 + 业务 `code` + 关键字段），并在登录请求中自动回写 token、在用户查询请求中自动回写 `userId`，支持串行跑通整条链路。鉴权负向用例覆盖「无 token / 伪造 token / 无权限角色」三类。

## 七、接口自动化（Python + Requests + Pytest）

18 条自动化用例，划分为三个层次：

- **会话层**：`token` 为 session 级 fixture，全程只登录一次，避免反复触发验证码；
- **数据层**：`created_user` 为用例级 fixture，自动创建并在用例结束后删除，不污染数据；
- **缺陷回归层**：把已识别的两个接口层缺陷固化为 `xfail` 用例，缺陷修复后会自动转为 `xpass`，直接作为回归信号。

## 八、主要发现

完整记录见 `bug-list/bug-list.md`，摘要如下：

| 缺陷 ID | 模块 | 问题 | 严重程度 |
| --- | --- | --- | --- |
| BUG-001 | 登录模块 | 同一浏览器多标签页登录不同账号时，后登录账号覆盖前一个账号的登录态 | 一般 |
| BUG-002 | 用户管理 | 密码仅校验长度，无字符类型要求，可设置 `123456` 纯数字弱口令 | 建议 |
| BUG-003 | 用户管理 | 手机号格式仅前端校验，表单与 Excel 导入两条通道均可提交非法规格 | 一般 |
| BUG-004 | 用户管理 | 用户名称首尾空格未 trim，账号创建后实际无法登录 | 一般 |
| BUG-005 | 用户管理 | 归属部门非必填，可创建无部门归属的孤儿用户 | 一般 |
| BUG-006 | 部门管理 | 部门循环引用仅前端拦截，接口层可写入环形结构 | 一般 |
| BUG-007 | 字典管理 | 同一字典类型下字典键值可重复，无唯一性校验 | 建议 |
| BUG-008 | 用户管理 | 批量导入失败提示只有错误序号，不含 Excel 行号 | 建议 |
| BUG-009 | 全局 | 异常响应直接返回 SQL 语句与服务器绝对路径 | 一般 |

**9 条缺陷全部经过实测复现，无推测条目**。**未发现致命级与严重级缺陷**。RuoYi-Vue 在业务逻辑层的保护校验做得相当完整：删除被用户引用的角色、被角色引用的菜单、含子节点的菜单与部门、已分配用户的部门，均能正确拦截；名称唯一性、必填校验、超级管理员保护、当前用户删除拦截也都有效。

已发现的问题集中在**前后端校验一致性**与**安全加固**两类：手机号、用户名空格、部门循环三条都是「界面拦住了、接口没拦住」的同一模式——页面操作时完全看不出来，只有走接口或批量导入才暴露。这属于开源项目「重功能、轻安全」的典型特征。

## 九、测试结论

- 用例 112 条，执行 112 条（执行率 100%），通过 106 条（通过率 94.6%）。
- 核心业务主流程与权限模型验证通过，功能层面达到可用标准。
- 缺陷 9 条，均为中低风险（一般 6、建议 3），全部实测复现，可逐条追溯到用例或接口请求。
- 建议优先修复三项：后端字段校验、密码策略、异常信息脱敏。
- 建议优先修复手机号后端校验与密码复杂度策略，消除「前端拦截、后端放行」的校验落差。
